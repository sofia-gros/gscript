# GScriptの2つの実行モデル

GScriptには、JS / TSへのコンパイルと、独自ネイティブランタイムを伴う機械語へのAOTコンパイルの2つの経路があります。入口となる型検査はGSコンパイラが担当します。

| 段階 | JS / TS | Native |
| --- | --- | --- |
| ソース | GS、GSモジュール、外部JS/TS | 静的GS、GSモジュール、外部C ABI宣言 |
| 検査 | GS型検査器、外部型のメタデータ読み取り | ネイティブ型検査器、ABI・整数幅・ポインター・呼び出し規約の検査 |
| 生成 | ES2022 JS / 型注釈付きTS | C11と小さなGSランタイム、その後機械語へ |
| 実行 | Node.js・ブラウザー等 | OSのネイティブ実行ファイル |
| ライブラリ | npm、Node、DOM、外部JS/TS | C ABI、OS API、静的・共有ライブラリ |

NativeのC11出力は中間表現です。Clang / GCC / Zigが最適化・命令生成・リンクを担当し、配布するアプリケーションは機械語です。GSの型検査をCコンパイラへ委譲しません。PythonはGSコンパイラの実装言語であり、生成されたネイティブアプリの実行環境には含まれません。

ネイティブランタイムは文字列の表現、出力、チェック付き数値演算等を担当します。Win32、ウィンドウ、描画、ゲームのイベントループを言語本体に固定する構成にはしていません。これらはGSモジュールからFFIを利用してライブラリとして実装できます。

v0.6.0はJS / TS経路と、実験的なネイティブ経路を配布します。ネイティブ経路は対応する静的な範囲を明示しています。同じGS構文でも実行モデルに応じた表現の違いがあります。詳細は[Native](native.md)と[ライブラリ互換性](library-compatibility.md)を参照してください。
