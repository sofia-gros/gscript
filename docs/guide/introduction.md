# GScriptとは

GScriptは、Go風の宣言構文でJavaScriptのAPIを使える静的型付き言語です。JavaScript / TypeScriptへの変換と、静的なGSコードのネイティブ実行という2つの使い方があります。

まず、次のコードを見てください。

```gs
func greet(name string) string {
  return "Hello, " + name
}
println(greet("GScript"))
```

出力は次のようになります。

```text
Hello, GScript
```

`func`は関数の宣言です。引数の名前の後に型を書き、`)`の後に戻り値の型を書きます。最後の行が関数を呼び出し、結果を表示しています。Goを知っていれば宣言構文に見覚えがあるはずです。JavaScriptを知っていれば、トップレベルで処理を実行する形に見覚えがあるはずです。

## このガイドの読み方

初めてGSを使う場合は、「はじめのプログラム」から順番に読み進めてください。各ページで1つの話題を扱い、コード・実行結果・その意味を説明します。必要な構文を探すときは左の章一覧や検索を使えます。

GoまたはJavaScriptの基本的な変数・関数の知識を前提にしています。Goの知識は必須ではありません。見た目が似ていても意味が異なる点は、関連するページと「Go・JSとの比較」に記載します。

## JavaScriptとネイティブ

JS / TS経路では、GSを静的に検査してからJSの実行環境で動かします。npm、Node.js、ブラウザーAPIと連携するコードはこちらで書きます。

ネイティブ経路では、静的なGSをC11に変換し、Clang / GCC / Zigで機械語へコンパイルします。JSエンジンを必要としませんが、v0.6.0では実験的な機能で、対応する構文と型がJS経路と異なります。

このガイドの「基本」と「型とオブジェクト」はJS / TS経路を説明します。「ネイティブ」で、その経路の型表現・メモリ・FFIを説明します。

## GoでもJavaScriptでもない理由

GSはGoのpackage、goroutine、channelを提供するGo互換言語ではありません。一方で、JSのすべての構文をそのまま受け入れる言語でもありません。Go風の型と宣言、JSのAPI・モジュールを組み合わせた独立した言語です。
